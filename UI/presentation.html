01 / Overview

Introduction & Project Overview

1

Next-Generation Assessments

ExamAI is a full-stack, cloud-integrated web application designed to administer exams remotely without compromising on academic integrity.

2

Granular Tri-Role Boundaries

Features specific, secured dashboard panels for Students (examinees), Examiners (test invigilators), and Administrators (system monitoring).

3

Embedded AI Proctoring

Integrates client-side ML vision libraries to track facial landmarks, detect cheating activities, and log browser anomalies locally.

ExamAI Highlights

  • MERN Stack (MongoDB, Express, React, Node)
  • Real-time websocket incident warning pipeline
  • Lightweight in-browser ML processing
  • Auto-saved state recovery on hardware fail
02 / Problem Statement

Problem Statement & Objectives

!

Lack of Visual & Browser Integrity

Standard online exams fail to prevent students from navigating to secondary tabs, using hidden search helpers, or allowing proxy candidates to attempt the test.

!

Exorbitant Cost of Live Invigilation

Live video streaming to human proctors consumes immense network bandwidth and suffers from visual fatigue, rendering it highly unscalable.

!

Disjointed Grading & Log Management

Most LMS solutions require examiners to manually review security alerts, evaluate subjective inputs, and chart result metrics on external apps.

Project Goals

  • Deploy robust local facial verification
  • Log tab, window, and focus switches
  • Automate evaluation & scoring engines
  • Render clean analytics dashboards

04 / Architecture

System Architecture & Telemetry

⚙

Decoupled Client-Server Layout

React 19 SPA frontend handles rendering and client-side ML logic. Node.js & Express API backend manages authentication, data storage, and grading logic.

🔒

Stateless JWT Security

Role-based router protection handles access parameters, verifying identity via jsonwebtoken. Password values are hashed using bcryptjs before DB write.

🗄

Cloud-Hosted MongoDB Atlas

MongoDB collections are integrated with Mongoose ODM schemas, ensuring clean indexing and highly scaling read/write transactions.

Information Flow

  • 1. Login & verification handshake
  • 2. face-api descriptor check
  • 3. Exam rendering + Active timers
  • 4. Proctor logs saved via Incident API
  • 5. Real-time Examiner panel updates
05 / AI & Proctoring

AI Proctoring & Face-ID Details

👁

Local Neural Networks

Using face-api.js, the application loads lightweight SSD Mobilenet V1 and Tiny Face Detector models directly inside the candidate's browser.

📊

128D Face Descriptors

Transforms raw camera frames into a 128-dimensional floating point vector. Computes Euclidean distance to match live feed against registration vectors.

⚠

In-Browser Event Capture

Listens to visibilitychange API triggers, flagging each tab transition. Dispatches AJAX requests to store incidents instantly on the MongoDB backend.

Telemetry Scored

  • Candidate Identity confidence score
  • Window tab switch counts
  • Camera absence durations
  • Multiple faces detected alert

07 / Tech Stack

Technology Implementation Stack

💻

Frontend Stack

React 19 (Hooks, Context API), Vite 8 (Hot Modules replacement), React Router DOM 7 (Dynamic routes protecting), Recharts (Examiner telemetry charts), Lucide React (vector assets).

☁

Backend Stack

Node.js, Express.js REST application layer. Multer middleware manages user file/image configurations. MongoDB Atlas cluster hosted database, parsed through Mongoose.

🛡

Security & AI Libraries

bcryptjs for backend hashing, jsonwebtoken for cryptographically signed session keys, face-api.js for browser TensorFlow model bindings.

Stack Summary

  • React 19 & Vite 8
  • Node.js / Express.js
  • MongoDB Atlas (Mongoose)
  • face-api.js (Local ML)
  • JWT & bcryptjs Security
